# `api-rpcs.md` — catálogo de RPCs callable de gym_app

Snapshot generado el 2026-05-21 a partir de:

```sql
SELECT p.proname, pg_get_function_identity_arguments(p.oid) AS args,
       pg_get_function_result(p.oid) AS returns, p.prosecdef,
       has_function_privilege('anon', p.oid, 'execute') AS anon,
       has_function_privilege('authenticated', p.oid, 'execute') AS authd
FROM pg_proc p JOIN pg_namespace n ON n.oid=p.pronamespace
WHERE n.nspname='public' AND p.prokind='f' AND pg_get_function_result(p.oid) NOT IN ('trigger','event_trigger')
ORDER BY p.proname;
```

en el proyecto Supabase `bvexjanqmfypmtgoapbt`.

**Cuántas son:**

- 56 funciones totales en `public` (incluye triggers).
- De ésas, **26 son callable por API** (no devuelven `trigger`/`event_trigger`).
- Todas tienen `GRANT EXECUTE` para `anon`, `authenticated` y `service_role`. El control real de acceso lo hace **el cuerpo de la función** (verificación de `auth.uid()` + role) o RLS al tocar las tablas. Tener `EXECUTE` para `anon` ≠ "público", pero igual amerita revisión caso por caso → ver `diagnostico_arquitec/10_*` §Estratégico.

**Cómo leer la tabla:**

- **Security:** `definer` → bypassea RLS, ejecuta como owner. `invoker` → respeta RLS del caller.
- **Usado en:** ruta del front que la llama. `cron/edge` = sólo se invoca desde `pg_cron` o desde una Edge Function. `(no usada)` = el grep en `src/` no la encontró — candidata a `REVOKE` cuando se haga hardening de anon.
- **Rol esperado:** quién está autenticado en el caller, según la lógica interna de la función (no según el `GRANT`).

## Pendiente para futuro hardening

Cuando se ataque el tier "RPC anon hardening" del handoff `10_*`, evaluar `REVOKE EXECUTE FROM anon` en:

- Todas las "(no usada en front actual)" de las secciones de arriba (≈11 RPCs).
- Mantener `EXECUTE FROM anon` SÓLO en las que el intake público sin login realmente usa: `process_intake_submission`, `_intake_map_nivel`, `_intake_parse_frecuencia`.

El universo total a revisar son **26 callable**, no las "47" que figuraba en el handoff `10_*` (ese número incluía triggers).
