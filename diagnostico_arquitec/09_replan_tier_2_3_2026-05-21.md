**Fecha:** 2026-05-21
**Insumo:** mapeo completo de `src/features/workouts/pages/TodayWorkoutPage.jsx` (2269 LOC) y `src/features/evaluations/pages/EvalWorkoutPage.jsx` (2259 LOC).

## 2. Por qué un hook común sería un error

Un `useWorkoutSession(planId, mode)` con `mode = 'today' | 'eval'` tendría que:

- Recibir 30+ params (un set para cada modo).
- Devolver 30+ valores (uno para cada modo).
- Lógica interna `if (mode === 'today') { ... } else { ... }` en cada función.
- Imposible de tipar limpiamente cuando llegue TypeScript (Tier 3.3).
- Cualquier feature nueva en una de las dos páginas obliga a tocar la API del hook.

Es **anti-patrón**. La duplicación no es lo que parecía; un hook compartido aumenta la fricción en vez de bajarla.

Si en el futuro aparece una **tercera página** con flujo similar (ej. una página de "warm-up del día" o un editor de plan from-the-student), recién ahí tendría sentido extraer un hook común. Hoy con 2 instancias el costo de la abstracción supera el beneficio.
